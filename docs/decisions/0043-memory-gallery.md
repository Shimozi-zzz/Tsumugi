# 0043 · 记忆回廊基础版（Phase C，仅自由查询）

日期：2026-08-09
状态：已接受
基准：docs/product-brief-v1.1.md（六.2 全局维度·记忆回廊）+ prompts/03_PhaseC

## 一、范围

新增全局"记忆回廊"页面：自由浏览全部 Memory，按**年份**与**作品**筛选；入口 =
主导航 + 命令面板。调 Phase A 的 `GET /memories` 全局接口。

**本轮明确不做**（提示词与 v1.1 一致）：意外重逢/"往年今日"（Phase E）、轻量记录类型
（Phase D）、作品类型泛化（Phase F）、RAG 语义检索接入（本轮是结构化筛选，不是语义搜索）。

## 二、展示形式选型：按年份分组的编年列表（不是热力图网格）

- v1.1 举例"2022/2023/2024/2025/2026 以及 某作品/某角色/某标签…"，参考选项是
  活跃度热力图（年度网格）或时间轴列表；
- **选择编年列表**的理由：热力图表达的是"活跃度/频率"（有多少格子亮着），而回廊要
  表达的是"内容/记忆"（那条日期那条摘要是什么）——网格看不清"哪一年有什么记忆"，
  列表可以直接承载"日期 + 作品名 + 摘要 + 点击跳转"；
- **空间隐喻**：回廊 = 一条走廊，从"现在"往回走。因此整体**时间倒序**（最新在前），
  按年份分组（年标签如书档，`--accent` 字 + 细分隔线 + 条目计数），组内继续倒序；
- 条目 = `MM-DD · 作品名` + 摘要，`--panel-border` 细竖线 + `--accent` 圆点，与
  Phase B 的作品时间轴同一套视觉语言，无新风格（ADR 0020）。

## 三、筛选维度范围与取舍

- 本轮实现两个最基础维度：**年份**（数据中实际存在的年份 chip，点击筛选/再点取消）
  与**作品**（下拉：全部作品 + 出现记忆的作品）；
- **本轮不做**：标签/角色/时间段/记录类型筛选——理由：① Memory 表本身没有标签字段，
  按标签筛需要后端 join memories→items→tags，属后端改动，不是纯前端筛选；② 时间段
  已被年份覆盖（年份即"某年"这一档）；③ 角色筛选同理依赖作品关联。这些留待后续按需
  追加，需要时再扩展 `GET /memories` 的筛选参数。

## 四、数据获取与性能

- 当前策略：一次拉全量（`GET /memories?limit=500`）后客户端按年份/作品筛选；
  个人库体量（几十~几百条）下无压力，且切换筛选零请求延迟；
- 后端接口已支持 `item_id/start/end/skip/limit`（Phase A），数据量明显增大后迁移为
  server 侧分页（参考现有资料库网格的分页方式），前端结构无需大改。

## 五、入口

- **主导航**：新增"记忆回廊"图标键（`SORTABLE_KEYS` 可排序），与 AGENT_UI_v2.1
  "记忆回廊（Memory Gallery）"空间命名一致；
- **命令面板**：`commands.js` 注册表新增「打开记忆回廊」（keywords：记忆/回廊/memory/
  回忆/时间轴）。

## 六、空状态

- 完全没有 Memory：引导"记忆回廊还是空的。收藏作品、写书评、留下记录，这里会慢慢
  长出属于你和这些作品的记忆。"
- 有数据但筛选无结果：分别提示"还没有 N 年的记忆 / 这个作品还没有留下记忆"。
