# 0044 · 往年今日（意外重逢，Phase E）

日期：2026-08-09
状态：已接受
基准：docs/product-brief-v1.1.md（六.2 被动重逢 + 七"意外重逢"的人格化方向）+
prompts/03 后续批次说明

## 一、范围

打开应用（首页神殿场景）时，若"去年今天"或更早某年的今天真实存在一条 Memory，由
猫娘用一句话具体唤起（引用年份/作品/摘要）；未命中不触发，保持既有日常问候逻辑。
本轮：后端跨年同月同日查询 + `matchScene` 最高优先级整合 + 台词模板 + 点击跳转只读弹层。

**本轮不做**：轻量记录类型（Phase D）、Memory 素材类型扩展、AI 生成台词、把"往年今日"
做成系统通知/弹窗（必须是猫娘人格说出口，v1.1 七节）。

## 二、多条记录选取规则：优先最近年份，同年同日取该日最新一条

- 后端 `query_on_this_day` 返回全部命中，按 **年份倒序、同日 occurred_at 倒序** 排序；
  前端取**首条** = 最近年份（去年优先）且该日最新的一条；
- 理由：v1.1 的默认画面就是"你去年的今天，写下了关于这部作品的一段话"——**最近年份
  最可感、最 relatable**；同一天内写多条时，最新一条代表"那天最后的想法"，最有临场感。
- 否决了"内容更完整的一条"：summary 是短摘要，很难客观定义"完整"，且近期短记录比
  远古长记录更适合"往年今日"的亲密唤起。
- 台词用 `yearsAgoLabel` 输出"去年的今天 / N年前的今天"，而非把年份数字直接塞进句子。

## 三、触发优先级：插入最高位（高于"想念"）——确认

`matchScene` 顶部新增 `on_this_day` 判定：`ctx.onThisDay`（后端命中的 Memory）非空即返回
`{ scene: "on_this_day", memory }`。优先级变为：

**往年今日 > 想念 > 里程碑 > 新收藏 > 写书评 > 时段问候 > 兜底**

理由（采纳任务描述）：往年今日的触发条件天然稀疏——一年里绝大多数日子都不命中，
只有真实存在历史同月同日记录的那几天才触发，**不会频繁抢占其他场景**；一旦命中，
说明这是当天最有分量的时刻，应优先展示。未命中时 `onThisDay=null` 走原逻辑，零影响。

## 四、台词与交互

- 台词模板（`MASCOT_LINES.on_this_day`，5 句，喵～占比 1/5）带占位符
  `{yearsLabel}/{title}/{summary}`，由 `selectLine` 用命中的真实 Memory 填充：
  "主人，{yearsLabel}的今天，你为《{title}》写下了「{summary}」。"——具体唤起，
  不是泛泛的"我记得你以前来过"；遵守 mascot-persona（称呼"主人"、情绪直给、喵～克制）。
- 命中时台词区上方加一行 `◇ 往年今日` 小标签（`--accent`），台词变可点击；
  点击复用 **MemoryReviewModal**（本轮从 MemoryTimeline 提取为共享组件，
  Phase B 时间轴与 Phase E 共用同一只读弹层）打开对应书评全文。
- 查询失败（网络/后端异常）静默降级为日常问候，不影响首页。

## 五、闰年 2-29 边界：严格同月同日，不做前移/后移（确认）

- 查询用 `strftime('%m-%d', occurred_at) = '02-29'`——2 月 29 日的记忆**只在 2 月 29 日
  当天命中**（闰年才有），2 月 28 日不前移匹配；
- 理由：2-29 的记忆每 4 年（下一个 2-29）仍会自然重逢；若在 2-28 把"去年的 2-29"
  拉出来，日期对不上，会变成"前天/昨天"式的模糊，破坏"同月同日"这个约定本身；
- 非闰年 2-28 想补上"那年 2-29"属于产品决策，本轮不做（保持简单可预期）。

## 六、坑位（SQLite）

`strftime('%Y', occurred_at) < 2026` 恒为 false：strftime 返回 **TEXT**，SQLite 比较规则
数字 < 文本，所以文本年份与整数字面量比较永远 false。必须
`cast(strftime('%Y', occurred_at) AS INTEGER) < max_year`（substr 同理）。本轮已修，
并有针对性测试（`test_leap_day_strict` / `test_strict_month_day_and_max_year`）。
