# 0003 · Prompt 拼接模板与超长上下文截断

日期：2026-08-05
状态：已接受（Phase 1）

## 决策

### Prompt 结构（手写拼接，不使用 LangChain）

```
system: 你是个人知识库助手，只依据"参考资料"作答；
        资料不足时明确说明，不编造；引用需标注来源标题；用中文、简洁。

user:   【参考资料】
        [1] 来源：《标题》
            内容…
        [2] 来源：《标题》
            内容…

        【用户问题】
        <query>
```

要点：
- system 明确"只依据资料 + 不编造 + 标注来源"，这是 RAG 抑制幻觉的关键。
- 每条参考资料带 `[n]` 序号与来源标题，方便 LLM 引用、也便于前端展示。
- 检索结果已按相关度降序，因此上下文中越靠前越重要。

### 截断策略

- 以**累计字符预算** `max_context_length`（默认 4000，中文按字符计）控制。
- 按相关度顺序逐条填入；预算耗尽即停止。
- 若**单条** chunk 超出剩余预算，则在该 chunk 内部截断并追加
  `…（此条已截断）` 标记，**保留它而非丢弃**——因为它是当前剩余最相关的
  一条，丢弃会浪费预算。

### DeepSeek API 调用与异常处理

- 直接 `httpx` 调用 `POST {base}/chat/completions`，手写 SSE 解析
  （`data: {...}` / `data: [DONE]`）。
- 模型 `deepseek-chat`，`temperature=0.2`（检索问答场景偏向事实稳定）。
- 超时：单次 `timeout=60s`（connect 10s）。
- 重试：非流式对 `Timeout/NetworkError` 重试 `llm_max_retries`（默认 1）次；
  流式不重试（避免连接/输出中途状态复杂）。
- 错误映射为面向用户的 `LLMError`：
  - 未配置 key → 提示配置 `DEEPSEEK_API_KEY`
  - 401/403 → 鉴权失败
  - 429 → 限流
  - 400 → 请求参数错误
  - 其他 5xx / 网络错误 / 超时 → 通用失败信息（重试后）
- embedding 失败 → 在检索阶段抛 `EmbeddingError`，路由返回 **503** 与明确
  提示（如模型未下载/网络不可达）。

## 小决策

- `max_context_length` 用字符而非 token 数：切分侧已用字符计，保持一致、
  无需引入 tokenizer 依赖；代价是对长上下文可能略保守/略激进，后续可按
  `tiktoken` 精准化。
- `temperature=0.2`、`max_tokens=2048` 为默认值，可在 settings 调整。
- SSE 事件协议：`sources` → `chunk`* → `done`（或 `error`），统一 JSON 载荷，
  前端按 `type` 分派。

## 已知限制

- 截断按字符硬切，可能从一句话中间截断（已用"截断标记"缓解，不追求完美）。
- 无上下文压缩/多轮对话记忆（Phase 1 为单轮问答）。
