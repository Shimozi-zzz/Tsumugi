# 0032 · 声优/Staff 关系图谱（作品-角色-声优 三层关系网络）

日期：2026-08-08
状态：已接受

## 一、数据实测（先实测后设计，不凭猜测）

对真实库（tsumugi.db）扫描 `raw_metadata.detail.metadata.characters`：

- **61 个外部条目带 raw_metadata，56 个含角色**；
- **角色 1840 个**，其中**带声优（actors 非空）1597 个（87%）**，**缺失声优 243 个
  （13%）**——结论：声优字段**不保证 100% 完整**，图谱/接口必须容忍缺失；
- `actors` 是**归一化后的声优名字符串列表**（如 `["坂本真綾"]`），空串/纯空白串
  视为无效并跳过；
- **唯一声优 1020 个**，分布极度偏斜：只配 1 部作品的 663 个、≥2 部 357 个、
  ≥3 部 159 个、≥5 部 41 个、≥8 部 6 个——绝大多数声优只配一作（噪音），
  真正形成"跨作品关系网络"的是 ≥2 的那批。

**Staff 范围确认**：Bangumi `get_detail` 目前只取 subject + characters（角色含声优
actors），**没有**拉取作品级 staff（监督/脚本/原画等 persons 端点）；实测数据里也
只有角色的 actors。因此本轮**只做声优关系**（数据确定存在），staff 列入未来扩展
（Connector 增加 persons 拉取后再并入同一图谱）。

## 二、后端聚合接口 `/api/voice-relations`

复用角色墙"内嵌 + 实时聚合、不建独立表"的决策（ADR 0016 思路），从 raw_metadata
实时扫描聚合三层关系：

- 响应：`works`（作品）/ `actors`（含 `works→roles` 完整配音列表 + work_count /
  role_count）/ `stats`（actor_count / work_count / missing_actor_chars）；
- 去重：同一 (声优, 作品, 角色) 只记一条；同名角色跨条目重复出现 → roles 去重；
  空串/空白声优名跳过；
- 图谱阈值（配音作品数≥N）由**前端过滤**，接口返回全量（数据量小，前端调阈值
  无需重新请求）。

## 三、图谱可视化技术选型

**不引入力导向/图可视化重型框架**（避免打包体积膨胀，任务红线）。用**手写轻量
SVG + 确定性布局**：

- 布局：作品节点沿外圈圆周分布；声优节点先放到"其配音作品的几何质心"，再做
  70 轮简单重叠松弛（声优间排斥 + 向自身作品质心牵引）——这是力导向的**确定性
  一次算完近似**，没有实时 O(n²) 帧循环，上千节点一次布局即定；
- 角色节点置于"声优→作品"线段中点 + 垂直偏移（多角色不重叠）；
- 节点：声优 = accent 圆（半径∝配音作品数，越大越是枢纽）、作品 = surface-2 圆、
  角色 = 小圆点；边 = 声优→角色→作品 两段细线；
- 视觉全走 token（surface-0/1/2、panel-border、accent、tag-bg），无独立配色。

**性能阈值（依据实测数据）**：默认 `最低配音作品数 ≥ 2`——实测剔除 663 个只配
一作的孤立声优，剩 **357 声优 / 56 作品 / ~1160 角色**（1575 圆 + 2324 边）形成
可读的跨作品网络（这正是本功能的价值）。提供 **2/3/5/8 四档调节**：≥3 → 159 声优
(927 圆)、≥5 → 41 声优 (359 圆) 更稀疏易读；头部实时显示当前规模。

## 四、交互与入口

- 点**声优** → 下方详情面板展示 TA 的**完整配音列表**（作品 → 角色），并高亮其
  子图（其余节点淡化）；
- 点**作品 / 角色** → 复用主从视图：`setSection("library") + setLibView("list") +
  setDetailBrowseId(item_id)` 直接跳详情；
- **入口**：新增导航图标"声优图谱"（voice 区）+ 角色墙页"声优关系"按钮 +
  角色选中后面板里每个声优名字一键跳转 + **命令面板"打开声优图谱"动作项**
  （commands.js 注册，ADR 0031 注册表追加）。
