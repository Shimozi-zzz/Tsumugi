# 0042 · 作品记忆时间轴 + 详情页"世界/我的"双栏（Phase B）

日期：2026-08-09
状态：已接受
基准：docs/product-brief-v1.1.md（第十三节"打开一本属于我的书"）+ prompts/02_PhaseB

## 一、范围

本轮目标（v1.1 原文）：**"第一次真正让用户看到'这部作品在我这里留下了什么'。"**
- 作品详情页（主从视图"从"面板，ADR 0029）明确划分 **外部世界 / 我的记录** 两个区域；
- 新增 Memory 记忆时间轴组件（调用 Phase A 的 `GET /items/{id}/memories`）；
- 空状态处理；
- 顺带补做 **存量 Review → Memory 回填**（见第六节）。

**本轮不做**：记忆回廊页面（Phase C）、新素材类型/收藏时刻（Phase D）、AI 检索记录。

## 二、双栏布局方案：上下分区（不是左右分栏）

- 主从视图的"从"面板宽度有限（右栏 flex-1），左右分栏会挤压外部世界的 InfoTable /
  标签/角色与时间轴的可读性；
- 采用**上下分区**：上半"外部世界 · 世界如何描述它"（基本信息/简介/标签/角色，原内容
  原样），下半"我的记录 · 我如何理解它"（顶部细分隔线 + Memory 时间轴）；
- 两个区域各用 `text-[11px] tracking-wider` 小节标题，`--accent` 强调字 + `--text-secondary`
  副标题，复用现有 InfoTable / TagCapsule / 四套主题 token，**不引入新视觉风格**
  （严守 ADR 0020）。

## 三、时间轴排序方向：正序（旧→新）

- 选择**正序**的理由：这是"回望"而非"刷新最近"。v1.1 的核心闭环是"几年后再次打开 →
  看到过去留下的痕迹 → 重新理解当时的自己"——旧→新读起来像一部关于这段关系的编年史：
  *第一次相遇（第一篇书评）→ 中途的变化 → 最近的一次记录*，最能回答"我的观点有没有
  发生变化"；
- 每条显示：**发生时间（occurred_at 的日期）+ 摘要（Phase A 的 summary 字段，免实时
  关联查询长正文）**；时间轴用一条 `--panel-border` 细竖线 + `--accent` 圆点，编辑感、
  克制。

## 四、点击跳转：只读弹层展示完整书评（不拉编辑器）

- 点击 `source_type=review` 的记忆 → 轻量**只读弹层**，展示该书评标题/评分/状态/日期 +
  全文（复用 `renderMarkdown` + 现有 `.doc` 排版样式）；
- 不用 Review Studio（全屏编辑器）的理由：主从浏览是"快速翻阅"场景，把重型编辑器
  拉进这条链路会打断浏览节奏；"打开完整内容"只需只读展示，要编辑走原有书评入口；
- 未来 text/image/collection 等来源的记忆默认不可点击（降级不弹窗），组件已按
  `source_type` 分支，无需改结构。

## 五、空状态

无记忆（刚收藏还没写过书评）时显示引导文案："还没有值得被记住的时刻。写下第一篇
书评，这里会出现属于你们的记忆。"——不显示空白、不报错，并暗示"写书评会生成记忆"
这个 Phase A 机制。

## 六、存量 Review → Memory 回填（本轮补做，理由）

- ADR 0041 曾把"存量 Review 不回填"定为有意省略，并注明"Phase B 前单独任务"；
- 本轮若不回填，用户已有的 57 篇书评在时间轴里全是空的，"这部作品在我这里留下了什么"
  对存量数据不成立，与 Phase B 目标直接冲突——故本轮补做（属 AGENTS.md 规则 5 的
  "与当前任务强相关的小优化"，已在变更记录说明）；
- 实现：`memories.backfill_reviews(engine)`，启动时在 `create_all + ensure_schema` 后
  调用；**幂等**（只为没有对应 Memory 的 Review 补建，多次运行只补缺口）；summary 走
  同一套 `_review_summary`（标题优先，否则截断 40 字），occurred_at = Review.created_at；
- 规模：O(n) 查询，个人库体量可忽略。
