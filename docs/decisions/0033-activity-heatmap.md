# 0033 · 活跃度热力图（年度总结）

日期：2026-08-08
状态：已接受

## 一、活跃度权重计算方式

**活跃度（按天）= 书评数 × 2 + 新收藏数 × 1。**

理由：
- 数据来源（按任务指定）：**书评 = Review.created_at**；**新收藏 = 外部条目
  （source != 'local'）的 Item.synced_at**（收藏入库时间）；
- 权重拉开：书评是用户**主动创作的内容**（写感想/打分，投入与信号都更高），
  收藏是一次相对轻量的保存动作（搜索+入库）。`书评×2` 让"深度投入"的天在热力图上
  更突出，而不是被大量轻量收藏淹没；两者的比值保持整数且足够直观（1 条书评 ≈
  2 个收藏的活跃度）。
- 明确不计入：本地笔记/图片的 created_at（既不是书评也不是外部收藏，任务范围外，
  列为未来扩展）；重复收藏的 synced_at 刷新会归属到当天（幂等刷新动作，可接受）。

## 二、后端聚合接口 `GET /api/activity?year=`

- `app/stats.get_activity_summary(db, year)`：扫描 Review.created_at 与外部 Item 的
  synced_at，按 `YYYY-MM-DD` 分组 → `{date, reviews, collections, score}`，只返回当年
  有活跃记录的日期（非零天，payload 极小）；
- 统计摘要：total_reviews / total_collections / total_score / active_days /
  busiest_month（当月总得分最高）/ longest_streak（score>0 的最长连续天数）；
- **跨年边界**：只计入 `year-` 前缀的日期（2025-12-31 与 2026-01-01 分属不同年，
  各自年份查询互不串扰，pytest 覆盖）。

延续 InspectorPanel 已验证的**手写 SVG 图表**路线（延续声优图谱"不为炫技引入重
依赖"的判断），不引图表库：

- **GitHub 贡献图风格**：一格一天、按周排成年度网格（对齐到周日、列=周），
  单元格 11px + 2px 间距；
- **档位**：0/1/2/3/4 五档，深浅 = `color-mix(in srgb, var(--accent) X%, transparent)`
  （X = 22/42/62/85），**基于当前主题 accent 色系**，不引入独立配色，四套主题统一
  生效；零分天用 `--surface-2` 浅底、未来格透明；
- **悬停详情**：每格内嵌 `<title>` 显示 `2026 年 8 月 7 日：57 条书评 · 57 个收藏`；
- 顶部月份标签 + 左侧星期标签；图例"少→多"。
