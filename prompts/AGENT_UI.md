## 【重要：本文档的定位与执行范围】（v2.1 新增，必须先读）

本文档是 Tsumugi UI 设计的**长期北极星**，描述的是完整愿景下"这个
应用最终应该长什么样"，**不等于"下一次开发任务应该一次性全部做完"**。

具体某一部分对应在哪个开发阶段执行、以什么顺序推进，以
`docs/product-brief-v1.1.md` 的 Phase 排期（Phase A 记忆核心 → Phase
B 作品记忆时间轴 → Phase C 记忆回廊基础版 → Phase D 记忆素材扩展 →
Phase E 意外重逢 → Phase F 作品模型泛化 → Phase G Personal RAG）为准。

任何单次开发提示词，只应该实现当前阶段范围内、被明确指派的部分。看到
本文档描述了某个尚未排期的能力（比如"AI 检索会话自动写入记忆回廊"），
**不代表这次任务就该顺手做掉**，除非任务本身明确要求。这是本项目此前
多次因为"agent 看到愿景文档就自主扩大范围"而返工的教训（详见"开发
流程简报.md"里 Review Studio 玻璃拟态那次的坑位记录），本轮起严格
遵守。

【项目定位】

Tsumugi 不是普通的 AI Chat，也不是普通的番剧收藏网站。

它是一座"会记住主人的二次元私人知识图书馆"。

核心概念：

Personal Knowledge Library
+
Anime Archive
+
Japanese Shrine
+
Personal Memory
+
AI Librarian

用户收藏的作品、笔记、书评、角色、声优、外部百科资料，
都应该被视为"图书馆中的馆藏"。

AI 不是独立聊天机器人，而是图书馆中的"检索与记忆能力"。

【现有技术能力】

项目已经具备（与"开发流程简报.md"逐条对齐，v2.1 校正）：

- 标签系统
- 外部 Connector：**Bangumi（含真实 OAuth 批量导入）、萌娘百科、

- 看守猫娘（软萌型人设，ADR 0040，固定台词库，场景触发）
- 数据备份 / 导入 / 导出（JSON 格式，幂等合并，已验证真实闭环）
- 本地代码级插件系统（无沙箱，开源信任模型）
- 命令面板（Ctrl+K，可扩展注册表）
- 四套收敛主题（经典白/薄荷浅蓝/樱花粉/深色）+ 有约束自定义

【设计目标】

不要设计成：
- 普通 Dashboard
- Notion clone
- AI ChatGPT clone
- Bangumi clone
- 二次元资源站
- 粉紫色模板网站

必须体现：

"这是一座属于我的、会记住我的图书馆。"

【视觉方向】

整体：

Quiet Japanese Private Library
+
Modern Anime Archive
+
Subtle Shrine Atmosphere
+
Editorial UI

视觉关键词：

- quiet
- elegant
- intimate
- atmospheric
- archival
- Japanese
- anime
- premium
- personal
- slightly mysterious

二次元元素必须克制。

不要大量使用角色立绘。
不要堆叠装饰。
不要到处使用发光效果。
不要使用厚重阴影。
不要使用大量渐变按钮。

【核心视觉比例】

70%：
图书馆 / 档案馆 / 编辑设计

20%：
日式神殿 / 仪式感 / 空间感

10%：
二次元 / 猫娘 / Anime culture

【核心设计原则】

1. 内容优先
2. 空间隐喻优先于装饰
3. 动画必须服务于空间感
4. 二次元元素必须与功能绑定
5. 不为了"好看"而增加无意义 UI
6. 所有视觉效果必须能够解释其存在原因
7. 保持信息密度与可用性
8. 保持长期使用不会疲劳

## 【应用外壳：图书馆的空间结构】（反模板审查 v2 新增）

三栏桌面壳（图标导航 + 侧栏 + 工作区）最容易滑向"工具仪表盘"。把它当作
**一座图书馆的建筑平面图**来命名与组织：

- **导航栏 = 图书馆的各馆/阅读室**，不是功能菜单。命名与图标都要是空间名词：
  - 问答 → **检索台**（Library Desk）：馆内检索与借阅台，不是 Chat
  - 图书馆 → **书库**（The Stacks）
  - 角色 → **人物档案馆**（Person Archive）
  - 声优图谱 → **关系厅**（Relation Hall）
  - 年度总结 / 记忆功能 → **记忆回廊**（Memory Gallery）：这里展示的
    是"这座图书馆记得你做过什么"（v2.1 起全文统一使用"记忆回廊"译名，
    与 `product-brief-v1.1.md` 及 Phase A/B/C 开发提示词保持一致）
  - 设置 → **管理室**（Archive Office）：唯一的"功能性"房间，刻意放最后
- **侧栏 = 馆内导览**：分组/标签/检索历史，定位是"找书"，不是"筛选数据"。
- **统计数字重新定位**：活跃度/数量不是 KPI 看板，而是**"图书馆的馆藏目录与阅读史"**
  ——数字出现在语境里（"书库共 X 册"），不单独做成仪表盘。
- 每一屏都应该能回答："我现在在图书馆的哪个空间？"如果不能，就是工具壳。

## 【排版与视觉层级系统】（反模板审查 v2 新增，v2.1 补充 token 归属）

"编辑设计（Editorial）"是反模板的核心，靠排版而非卡片建立层级：

- **字体**：标题用衬线（serif，中文字符可用宋体系），正文用现代无衬线；
  章节小标签允许竖排文字（vertical-rl）做点缀，点到为止。
  **v2.1：这一条需要落地为共享 token**——在 ADR 0020 已有的共享 token
  体系（间距/圆角/阴影/密度）基础上，新增 `--font-heading` /
  `--font-body` 两个字体 token，四套主题共用同一套字体规则，不要把
  字体样式散落写死在各组件里，执行时需要走一次正式的 token 扩展任务，
  不是零散加 CSS。
- **信息层级**：用字号/字重/行距/留白建立层级，而不是用边框和背景色。
- **网格**：页面网格基于文字基线；封面统一 2:3 比例。
- **圆角层级（反模板关键）**：
  - 封面 / 缩略图：允许中等圆角（它们是"馆藏实物"）
  - 控制件（按钮 / 输入框 / 标签）：小圆角
  - 正文 / 列表 / 表格 / 面板 / 卡片容器：**近直角**（存档感、编辑感）
  - 禁止"所有元素统一大圆角"的模板观感。
- **卡片治理**：
  - 卡片只允许用于**物理馆藏对象**（封面+标题的"一本书/一件藏品"）
  - 其余内容用 **分隔线 + 留白 + 编辑列表** 组织
  - 禁止卡片套卡片、禁止为分组而造卡。
- **渐变 / 发光 / 阴影规则**：
  - 渐变**只用于氛围光**（封面取色），禁止用于按钮、面板背景、内容表面
  - 发光**只允许出现在单一焦点时刻**（取书、仪式揭幕），一次屏幕只有一个"发光的对象"
  - 层级用**细描边 + 少量留白**表达，禁止厚重阴影；阴影是氛围（柔和、大范围、低透明度），
    不是"立体浮起"。

## 【首页】

首页不是 Dashboard。

它应该像：

"进入图书馆之前的神殿入口"。

使用：

- 大面积留白
- 极简鸟居轮廓
- 中央搜索入口
- 最近收藏作为"最近供奉"
- 最近作品封面形成纵深排列
- 封面主色影响环境光
- 极轻微的仪式感过渡
- 看守猫娘只提供低存在感文字

神社元素的职能映射（防止装饰化退化）：

- 鸟居轮廓 = **入口方位**：宣告"你正站在图书馆门口"
- 中央搜索栏（祭坛）= **焦点**：进馆的第一步
- 最近供奉（纵深封面）= **馆藏陈列**：最近的收藏
- 封面主色环境光 = **当前焦点作品**：这束光来自你最近在关注什么
- 仪式过渡 = **节奏**：一天一次"入馆"的仪式感，不是 loading

**v2.1：以上首页核心结构已实现（ADR 0039），本节描述的是现状而非
待办，如需改动请明确是"调整现有实现"而不是"从零设计"。**

不要：
- 卡片堆满屏幕
- 大型 Banner
- 大型角色立绘
- 大量统计数字

## 【图书馆】

设计为真实的私人书库。

支持两种视图（**v2.1：现有实现是三种——网格/书架/状态分组列表，本节
只讨论其中的 Book Shelf 与 Archive Grid 两种，状态分组列表本节未涉及，
不受本节改动影响**）：

1. Book Shelf
2. Archive Grid

**Book Shelf（真书架，不是"书脊贴成的列表"）**：

> **v2.1 重要标注：这一节的要求（层板线、真实数据驱动的书脊厚度、
> 取书/开书动画）是对现有实现的一次有意推翻，不是增量调整。**
> 现有书架实现（ADR 0019）明确选择了"书脊颜色按标签哈希规则分配，
> 不引入取色库/Canvas 复杂度做真实物理属性驱动"，这是当时经过权衡
> 的决定。本节要求的"真书架"效果价值更高、也更符合图书馆隐喻，值得
> 做，但执行时必须：(1) 在对应 ADR 里明确写"这是对 ADR 0019 的有意
> 推翻，理由是……"，不能悄悄改掉旧决定；(2) 现有的书脊配色 hover 取色
> 联动（ADR 0037）需要在新设计里保留或说明如何整合，不要重复造轮子。

- **横向层板线**：书架有可见的层板（shelf line），书"站在"层板上，有地面感
- **按系列/分类分架**：同系列作品放同一层/相邻，层板有类别小标签（如"命运石之门""今年补完"）
- **书脊厚度来自真实数据**：书脊宽度与该作品的内容长度/笔记数量相关（是"这本书有多厚"的隐喻）
- **封面色彩**：书脊透出封面主色，让书架本身有色彩节奏
- **hover = 取书**：书轻微上浮 + 局部环境光（shelf focus），暗示"要把它拿下来"
- **点击 = 书滑出打开**：从书架位滑出，衔接作品详情的"翻开这本书"

**Archive Grid**：
- 大封面（2:3，统一基线对齐）
- 极简元数据：标题、来源、标签
- **弱化"追番状态"徽章**（那是 Bangumi 的语言，指"想看/在看/看完"这类
  阅读状态）；状态改为低对比度小字，或融入书签/页签隐喻（"读到这里"），
  重心放在"我记录了什么"（笔记/书评/记忆的密度标记）
- 禁止状态徽章五颜六色堆在封面上
- **v2.1 澄清：以上"弱化"仅针对追番状态徽章，不包括数据来源徽标**
  （卡片上标注该条目来自 bangumi/moegirl/vndb 的那个标签，`TagCapsule`
  组件，此前修过文字截断问题）。来源徽标承载"这条数据的可信来源/
  出处"这个实际信息价值，不属于本节要弱化的对象，除非任务明确要求
  改动它。

## 【作品详情】

不要叫 Detail Page。

设计为：

**"打开这本书"——双页结构（反模板审查 v2 强化）**。

一本摊开的书有两页：

- **左页 = 外部世界档案（这本书本身）**：封面、标题、简介、标签、来源、角色、
  外部百科、与其它作品的关系 ——"世界如何描述它"
- **右页 = 我的理解（我的阅读记录）**：我的笔记、我的书评、我的标签、我的记忆
  时间线、"我为什么喜欢它" ——"我如何理解它"

视觉上用页面结构（中线分割 / 不同底色温度 / 两侧不同排版密度）把两个世界分开，
而不是只靠角标。这是 Tsumugi 区别于"二次元版 Bangumi"的关键页。

详情还包含：AI 问答（以检索记录形式，见【AI】）、时间线（与记忆回廊联动，
对应 Phase B「作品记忆时间轴」的实现范围）。

## 【AI】

不要做普通 Chat UI。

设计成：

**Library Query（检索记录，文献形态）**

当用户提问时：

1. 显示"正在翻阅馆藏"（检索过程是一段翻书/检索的节奏，不是 spinning loader）
2. 显示检索到的来源，区分：我的笔记 / 我的书评 / 外部百科
3. AI 回答
4. 来源可点击（点开 = 打开对应馆藏）

反模板约束：

- **没有聊天气泡、没有头像、没有消息线程**。回答是一份**文献**：有标题、有分段、
  有"引用馆藏"的脚注式来源（书名/章节/来源类型），像书页而不是聊天记录
- **AI 是"图书馆的检索与记忆能力"，不是一个悬浮聊天机器人**

**v2.1 重要标注：以下这条描述的能力属于未来 Phase（预计 Phase D 或
之后，需与"每次检索会话自动写入记忆回廊"的具体设计一并单独排期，
当前 01/02/03 号开发提示词均不包含此项）——"每次检索会话自动写入
记忆回廊，成为一条'检索记录'"。这需要在 Memory 的 `source_type` 里
新增一个 `query`/`session` 类型，并设计对应的落地规则（比如什么样的
检索算"值得记住"，是否每次问答都记、还是需要某种触发条件），执行前
需要单独讨论确定，不要在做 AI 问答界面改版时顺带实现这条。**

本节其余部分（检索过程的呈现节奏、来源分组展示、无聊天气泡的文献式
排版）不依赖上述"写入记忆回廊"能力，可以独立执行。

## 【记忆回廊】

设计一个非常重要的模块：

Memory Gallery（记忆回廊，v2.1 起全文统一使用此译名）

记录：

- 收藏时间
- 第一次笔记
- 书评
- 标签变化
- AI 检索记录（会话）——**v2.1：属于上述【AI】小节标注的未来 Phase，
  不在当前基础版范围**
- 相关作品
- 用户自己的观点

**v2.1：本模块的基础版本（Phase A 记忆核心数据结构 + Phase B 作品
维度时间轴 + Phase C 全局自由查询）已有独立的开发提示词（见
`01_PhaseA_Memory核心数据结构.md` / `02_PhaseB_作品记忆时间轴.md` /
`03_PhaseC_记忆回廊基础版.md`），本节是这三份提示词之上的完整愿景，
包含"标签变化""AI 检索记录"等尚未排期的素材类型（对应 Phase D/E），
执行任何相关开发前，请先确认当前处于哪个 Phase，不要越级实现。**

**地位（反模板审查 v2 强化）**：记忆回廊是"反 Dashboard"的核心证据——它把
"使用记录"变成"记忆"。首页的猫娘台词、详情页的时间线、年度总结，都从它取数据。
每个作品详情页都内嵌一段它的"迷你时间线"。

目标：

让用户能够回答：

"我什么时候认识这部作品？"

"我为什么喜欢它？"

"我过去是怎么评价它的？"

"我的观点有没有发生变化？"

## 【猫娘】

猫娘不是客服。

不是聊天机器人。

不是一直弹窗的 AI。

她是：

**"住在图书馆里的看守猫娘"，同时也是"记忆的记录者"（反模板审查 v2 升级）**。

她的角色不是装饰性问候，而是**图书馆的记忆之声**：

- 台词引用真实馆藏状态（新收藏、里程碑、久别、书评、时段）
- 她帮助用户"意识到自己在这座图书馆里做过什么"（例如记忆回廊里的关键节点由她点出）
- 她只在这个角色成立时才出现，不刷存在感

**v2.1：现有猫娘人设（`docs/mascot-persona.md`）已确定为软萌黏人型、
固定称呼"主人"、口癖"喵～"克制使用（≤50%），本节的"记忆记录者"定位
是对现有人设的角色深化，不是替换或新增另一套人设，未来涉及"往年今日"
等新触发场景（对应 Phase E），台词写作需延续 `mascot-persona.md` 已
定义的规则，不要另起一套语气。**

她只在合适的时机出现。

例如：

- 用户很久没打开图书馆
- 新收藏
- 完成第一篇书评
- 达到收藏里程碑
- 特定时间段

表现方式：

极少量文字。

不要弹窗。
不要气泡占据主要空间。
不要打断用户。

## 【动画】

动画应该具有"仪式感"。

推荐：

- fade
- subtle slide
- depth transition
- book opening（取书 / 开书）
- ambient light transition
- shelf focus
- soft blur

禁止：

- 大量 bounce
- 大量弹跳
- 快速缩放
- 过度粒子
- 炫酷 loading

**节奏规则（反模板审查 v2 新增）**：

- **默认安静**：动画只出现在"进入空间 / 状态变化"的瞬间，平时不自动动
- 单次时长 ≤ 200ms（仪式揭幕类可以到 1s 左右，但**按天限流**，不是每次，
  v2.1：现有首页揭幕动画已实现此规则，ADR 0039，可直接复用同一套
  "每日首次完整播放/同日简化版"的频率控制逻辑，不需要重新设计）
- **所有动画只服务于**空间转换（进馆、取书、开书、入夜），不为炫技
- 尊重 `prefers-reduced-motion`：用户系统关闭动画时，全部过渡退化为瞬时
- 禁止循环播放 / 持续漂浮 / 呼吸灯式的背景动画

## 【最终目标】

用户第一次打开时应该产生这样的感觉：

"这不是一个管理资料的软件。"

"我好像走进了自己的图书馆。"

第二次使用：

"它记得我收藏过什么。"

长期使用：

"这里真的保存了我的一部分记忆。"

请围绕这个目标重新设计 UI。

## 【反模板自检清单】（每个页面/每次改动前过一遍）

1. 这一屏是"图书馆里的某个空间"，还是功能仪表盘？（工具壳 → 否决）
2. 有没有无意义的卡片？（卡片必须代表"一本书/一件藏品"，否则用分隔线+留白）
3. 圆角是否遵循层级（封面可圆、控制小圆、正文/面板近直角）？
4. 渐变是否只用于氛围光？发光是否全屏只有一个焦点？
5. 有没有纯装饰的二次元/神社元素？（必须有数据或信息角色，否则删除）
6. AI 是否表现为文献/检索记录，而不是聊天气泡？
7. 作品详情是否体现"左页=外部世界，右页=我的理解"的双页结构？
8. 书架是不是真书架（层板线/厚度来自数据/取书/开书），还是书脊列表？
9. 状态/徽章是否克制？是不是把重心放在"我记录了什么"？（来源徽标不
   在弱化之列，见【图书馆】节 v2.1 澄清）
10. 猫娘是否出现在功能语境里（记忆/状态/时机），还是刷存在感？
11. 动画是否只在进入/状态变化时出现、≤200ms、尊重 reduced-motion？
12. 这一屏能不能解释"为什么长这样"？（解释不了 → 说明是模板）
13. **（v2.1 新增）这项改动是否越过了当前 Phase 排期？**（如果本文档
    描述的能力尚未在 `product-brief-v1.1.md` 的当前 Phase 里，不要
    在本次任务中顺带实现）
